# Kaggle CAFA Competition Solutions: Practical Techniques (CAFA-5 vs. CAFA-6)

**Scope note on competition identity**: CAFA-5 ("CAFA 5 Protein Function Prediction") ran on Kaggle in 2023 and is fully closed with public post-mortems. CAFA-6 ("CAFA 6 Protein Function Prediction") is hosted by Iowa State University (with Northeastern, UniProt, ISCB) with a $50,000 prize pool — [Kaggle launch announcement](https://x.com/kaggle/status/1978878346130784672) gave an entry deadline of Jan 26, 2026 / final deadline Feb 2, 2026. **Important finding: as of this research (Sept 24, 2026), CAFA-6 has already concluded** — this is not "too recent for post-mortems" as the task brief anticipated; at least one detailed, reproducible solution write-up is already public (see below). Every finding below is tagged CAFA-5 or CAFA-6 explicitly; do not conflate them — they are different label spaces, different final-evaluation windows, and (per one CAFA-6 write-up) a different scoring metric name (`mean f_micro_w` for CAFA-6 vs. the "modified F1-score"/weighted Fmax used in CAFA-5), so raw scores are not comparable across the two.

## What did top CAFA-5 solutions use as core approach (PLMs, classifier heads, loss functions)?

### Takeaway
Every placed CAFA-5 solution examined combined pretrained protein language model (PLM) embeddings (ESM-1b/ESM2/ProtT5/ProtBERT/Ankh, often several stacked together) with non-PLM signal (literature text mining, sequence alignment/BLAST, taxonomy, non-experimental/electronic GO annotations), fed into fairly simple heads (logistic regression, MLPs, gradient boosting) rather than exotic architectures — the winning ingredient was diversity of input signal and ensembling, not a single sophisticated model. Standard BCE loss was explicitly called out as a weak choice for this task's severe class imbalance; two independent top-10 teams reported switching away from it.

### Cited Findings
- **CAFA-5, 1st place (GOCurator, team led by Prof. Shanfeng Zhu, Fudan University)**: evaluated ESM-1b, ESM2, and ProtT5 and found "little difference in the scores achieved by these methods," ultimately using ESM-1b. Component models: **LR-MEM** (logistic regression on concatenated protein-description + literature + sequence representations), **GOXML** (AttentionXML, an extreme multi-label classifier for "fast high-precision large-scale multi-label classification"), **FoldSeek-KNN** (weighted voting from structural-similarity search), and **GORetrieval** (a deep-learning matcher doing semantic matching between GO term descriptions and literature/protein information, used for reranking). A learning-to-rank model combined the four component methods' outputs plus a 20-dim one-hot species vector. — [1st place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/gocurator-1st-place-solution-for-the-cafa5)
- **CAFA-5, 2nd place (ProtBoost, team U900 — Chervov, Vakhrushev, Fironov, Martignetti)**: embeddings from **Prot-T5** and **ESM2**, plus one-hot taxon (organism) features, fed into **Py-Boost** (a gradient-boosting library the authors built specifically for multi-target problems — trained to predict 4,500 GO-term targets in a single run, ~2 min/fold), a neural network, and logistic regression as parallel base models. A "Conditional Probability Modeling" (CondProbMod) technique re-parameterizes targets using GO's hierarchical tree structure to model conditional probabilities down the ontology rather than independent per-term probabilities. — [ProtBoost paper, arXiv:2412.04529](https://arxiv.org/pdf/2412.04529) (Chervov et al., "ProtBoost: protein function prediction with Py-Boost and Graph Neural Networks — CAFA5 top2 solution")
- **CAFA-5, 3rd place (tito)**: embeddings from **T5, ESM2t36, ESM2t48**, and combinations thereof; taxonomy one-hot restricted to the 90 taxon IDs present in the actual test set; non-experimental (electronically inferred) UniProt-GOA evidence codes (11 of them) one-hot encoded into a (batch, 11, n_labels) tensor and processed through a **1D-CNN with kernel_size=1**. Classifier head architecture, exact loss function, and hyperparameters were not detailed in the writeup. — [3rd place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/tito-3rd-place-solution-for-the-cafa-5-protein-fun)
- **CAFA-5, 4th place ("ProtGoat" per the ProtBoost paper's discussion; solution code at zongmingchua/cafa5)**: fused embeddings from **five** PLMs — ProtT5-XL, ESM-2 650M, ESM-2 3B, ProtBERT, Ankh-large — each mean-pooled, plus **taxonomy features** and **literature features** (TF-IDF over PubMed abstracts, filtered to GO-term vocabulary), on the reasoning that "where a protein has been studied, its literature names its functions directly, which is evidence sequence alone cannot provide." Each modality passed through dedicated layers before concatenation and a sigmoid output per GO term; three separate models handled the three GO aspects (BP/CC/MF) rather than one joint model. A "DAG-aware loss" was experimented with but explicitly **not used** in the final submission. — [GitHub: zongmingchua/cafa5](https://github.com/zongmingchua/cafa5)
- **CAFA-5, 5th place (StarFunc-based)**: the deep-learning component used **SPROF-GO**, itself built on a pretrained PLM. This was one of six inputs (five component-method predictions — sequence-based, structural, PPI-network-based, Pfam-based, deep-learning-based — plus a GO-term background-frequency "naive" prior) combined via Random Forest. — [5th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/hfm7zc-5th-place-solution-for-the-cafa-5-protein-f)
- **CAFA-5, 6th place (team Evans)**: used only the **last three layers of an ESM model** as input features, feeding several feedforward layers per GO aspect (three separate models, one per aspect). Explicitly **avoided standard BCE loss** "due to label imbalance challenges," instead combining (by multiplication) an "IA weighted soft F1 loss across both protein level and GO term level" with a ranking loss formulated as a logsumexp of zero-term minus positive-terms plus negative-term minus zero-term. — [6th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/evans-6th-place-solution-for-the-cafa-5-protein-fu)
- Per the ProtBoost paper's survey of the CAFA-5 leaderboard: the **Top6 team (Freddolino Lab)** independently also reported implementing a **"soft F1 loss"** that "significantly enhanced model performance compared to standard binary cross-entropy (BCE) loss" — a second, independent team reaching the same BCE-is-suboptimal conclusion as team Evans. The **Top5 team** (also Freddolino Lab) additionally exploited AlphaFold2 structural alignment, protein-protein interaction networks, and Pfam family membership. The **Top19 team (Hoehndorf Lab)** built novel ontology embeddings representing each GO node as a *ball* rather than a point, translating ontology axioms into geometric constraints and enabling zero-shot prediction for labels with zero training examples. — [ProtBoost paper §1](https://arxiv.org/pdf/2412.04529)

### Inferences
- Across independently-run top-10 CAFA-5 teams, PLM choice (ESM-1b vs. ESM2 vs. ProtT5) mattered far less than what non-sequence signal was fused in alongside it (literature text, taxonomy, alignment/structure, electronic annotations) — this looks like a genuine competition-level finding, not an artifact of one team.
- Standard BCE loss is a recurring pain point at this label cardinality/imbalance (2 independent teams in the top 6 moved off it toward soft-F1-style or IA-weighted losses).

### Gaps
- Exact hyperparameters (learning rates, batch sizes, layer counts) for the 1st, 3rd, and 5th place solutions were not present in the writeups fetched; would require the linked code repos/notebooks for full reproduction detail.
- Full text-mining/literature pipeline used by GOCurator (1st place) beyond "PubMedBERT, TF-IDF, Document2Vec" tool names was not detailed in the writeup.

## What validation strategies did top solutions use to generalize to genuinely novel proteins?

### Takeaway
Top CAFA-5 teams converged on **protein-level (not row-level) splits** and, more distinctively, **temporal/version-based holdouts using later UniProtKB/GOA releases** to mimic the true CAFA setup (predicting functions not yet experimentally verified at training time) rather than a naive random split.

### Cited Findings
- **ProtBoost (2nd place)**: "The models were trained using random 5 fold cross-validation scheme with GroupKFold on unique sequence" — i.e., grouped by protein sequence so no sequence leaks across folds; "the stacking was tested on small holdout subsample." — [ProtBoost paper §2.1](https://arxiv.org/pdf/2412.04529)
- **3rd place (tito)**: treated the problem "as time-series data" — validation annotations were pulled from the **latest UniProtKB release available during the competition**, explicitly excluding any sub-ontology data already present in the training set to avoid leakage. Training data originated from the **UniProtKB snapshot as of November 17, 2022**; the actual held-out test set consisted of annotations experimentally verified only **after August 22, 2023** — i.e. a genuine temporal holdout matching CAFA's real "novel function discovery" framing. — [3rd place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/tito-3rd-place-solution-for-the-cafa-5-protein-fun)
- **5th place**: evaluated component methods on "an independent test set based on UniProt-GOA release 2023-05-18" — again a later-release temporal holdout, used specifically to rank feature/component importance before finalizing the ensemble. — [5th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/hfm7zc-5th-place-solution-for-the-cafa-5-protein-f)
- **1st place (GOCurator)**: rather than a temporal split, selected validation proteins to **match the species distribution of the actual CAFA-5 test set** — a stratified-by-organism, 1000-protein validation set — reasoning that generalizing across the same taxonomic spread as the real test set mattered more than a temporal cut for their pipeline. — [1st place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/gocurator-1st-place-solution-for-the-cafa5)
- **6th place (Evans)**: used plain 5-fold random splits (not explicitly protein-grouped or temporal in the fetched writeup), with "5 different models for each GO aspect" and the final term score being the mean across the 5 fold-models. — [6th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/evans-6th-place-solution-for-the-cafa-5-protein-fu)
- **CAFA-6, 11th place (T0chka)**: used plain "5 folds" cross-validation across its base models (HMLP, MLP, PyBoost) — the public write-up does not describe a temporal or species-stratified split, in contrast to several CAFA-5 top-5 teams. — [GitHub: T0chka/cafa6_11th_place_solution](https://github.com/T0chka/cafa6_11th_place_solution)

### Inferences
- The two validation strategies actually used by CAFA-5's very top finishers (1st: species-distribution matching; 3rd and 5th: temporal/version holdouts) both directly target CAFA's core generalization challenge (novel proteins / newly-discovered functions), rather than simple random or protein-grouped k-fold, which several lower-placing or non-fetched teams used instead. This suggests validation-strategy sophistication tracked with placement, though the sample here (6 solutions) is too small to call this proven.

### Gaps
- Could not confirm whether the CAFA-6 11th-place solution's plain 5-fold CV was a deliberate simplification or whether higher-placing CAFA-6 teams used temporal/stratified splits — the CAFA-6 top-placing write-ups themselves could not be independently verified/fetched (see CAFA-6 section below).

## What GO DAG post-processing / label-propagation tricks were used?

### Takeaway
The dominant and simplest trick, used across multiple CAFA-5 and the one verified CAFA-6 solution, is enforcing the **true-path rule directly as a post-processing constraint** — propagating positive child-term calls up to all ancestors and/or clamping each parent term's probability to be ≥ its children's — rather than relying on the model to learn DAG-consistency implicitly. The 2nd-place CAFA-5 team went further, baking hierarchy-awareness into the *stacking* stage itself via a Graph Convolutional Network operating on the GO graph.

### Cited Findings
- **ProtBoost (CAFA-5, 2nd place)**: explicit post-processing step "based on the conventional assignment of GO labels in the CAFA challenges, that is if a child node have a label '1', then all its parent nodes will be assigned label '1' automatically" — implemented as "a procedure to leverage the property that the values of parent nodes are always greater than or equal to those of their child nodes" (i.e., clamps parent probability ≥ max of child probabilities). Additionally, the **stacking stage itself is a Graph Convolutional Network (GCN)** run separately per aspect (GCN-BP, GCN-MF, GCN-CC) that aggregates not just the base models' own predictions but also external electronic annotations (QuickGO, UniProtKB GOA) — using the GO graph structure natively at the meta-model level, not just as a final clamp. — [ProtBoost paper §2.1, Fig. 1](https://arxiv.org/pdf/2412.04529)
- **CAFA-5, 4th place**: experimented with a "DAG-aware loss" (training-time DAG consistency) as an alternative to post-hoc propagation, but this was **not used** in their final submission — its final model apparently relied on separate per-aspect sigmoid outputs without an explicit DAG-consistency loss term or described post-processing propagation step. — [GitHub: zongmingchua/cafa5](https://github.com/zongmingchua/cafa5)
- **CAFA-6, 11th place (T0chka)**: candidate GO terms undergo "propagation through the GO hierarchy," are then truncated to the "top 500 predictions per protein," and protein-level NOT-annotations are excluded where available in UniProt-GOA — a similar propagate-then-truncate post-processing pipeline as CAFA-5's top finishers, applied on the newer competition. — [GitHub: T0chka/cafa6_11th_place_solution](https://github.com/T0chka/cafa6_11th_place_solution)
- Per the ProtBoost paper's survey: the **Top19 (Hoehndorf Lab)** team took a training-time rather than post-processing approach to DAG consistency, using **ball/box-style ontology embeddings** whose geometry directly encodes ontology axioms (subsumption etc.), which also happens to enable zero-shot prediction of GO terms absent from the training set. — [ProtBoost paper §1](https://arxiv.org/pdf/2412.04529)

### Inferences
- There appear to be two competing philosophies: (a) cheap post-hoc true-path enforcement (clamp/propagate after inference — ProtBoost's final step, T0chka's CAFA-6 approach) vs. (b) baking hierarchy-awareness into the model/loss itself (ProtBoost's GCN stacker, the 4th place team's abandoned DAG-aware loss, Hoehndorf Lab's ball embeddings). The post-hoc approach is simpler and was used even by the eventual CAFA-5 runner-up as their *final* correction step, suggesting it remains close to necessary regardless of how sophisticated the upstream model is.

### Gaps
- Exact algorithmic detail of "propagation through the GO hierarchy" in the CAFA-6 11th-place solution (e.g., max-propagation vs. some smoothed variant) was not specified beyond the phrase itself.

## What ensembling strategies were used, and how much lift was reported?

### Takeaway
Every top-10 CAFA-5 solution examined was fundamentally an ensemble of heterogeneous component methods (not just a few random seeds of one model), typically stacked via learning-to-rank, GCN, or Random Forest meta-models — but reported lift from the ensembling step itself varied enormously, from "nearly all the value" (ProtBoost's ablation) to "almost none" (5th place's finding that a single component captured 98.7% of performance).

### Cited Findings
- **ProtBoost (CAFA-5, 2nd place) ablation table** (preliminary-leaderboard scores, component-by-component): Ridge regression baseline over Prot-T5 embeddings alone → **0.47**; single Py-Boost model + conditional probability modeling → **0.51**; + one-hot taxon features → **0.53**; + CondProbMod for Py-Boost and LogReg, blended with direct models → **0.55**; + external GOA electronic annotations → **0.57**; + ensembling with a neural-network base model → **0.59**; + final GCN stacking of all models and GOA → **0.62**. (Note: the *final* private-leaderboard CAFA-metric score reported for the submitted model was **0.58240** — third place scored 0.57276, fourth 0.56245 — so the 0.47→0.62 ablation-table trajectory reflects a different/earlier scoring phase than the final 0.5824, per the paper's own framing as "preliminary scores published throughout the various phases.") This implies each pipeline stage (taxon features, GOA data, NN ensembling, GCN stacking) added a measurable, non-trivial increment in this progression. — [ProtBoost paper, Table 1 and §2.2](https://arxiv.org/pdf/2412.04529)
- **CAFA-5, 4th place**: final submission was "an average of 25 networks (5-fold cross-validation × 5 seeds)" — i.e., the "ensemble" was largely repetition/averaging of the *same* architecture across folds and seeds rather than heterogeneous component models, on top of the multi-PLM feature fusion. — [GitHub: zongmingchua/cafa5](https://github.com/zongmingchua/cafa5)
- **CAFA-5, 5th place (StarFunc)**: combined 5 heterogeneous component methods (sequence, structure, PPI, Pfam, deep-learning) plus a naive-frequency prior via a **Random Forest with 4000 trees** (compared against GBDT with 1000 trees and DART, with RF winning) — but reported that "98.7% of the performance (in terms of wFmax) can be achieved by the sequence-based component alone," i.e. the six-way ensemble bought only ~1.3 percentage points over the single best component for this team. — [5th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/hfm7zc-5th-place-solution-for-the-cafa-5-protein-f)
- **CAFA-5, 6th place (Evans)**: linear combination of neural-network predictions (ESM-embedding-based, 5-fold-averaged) with an alignment-based method (blastp/diamond vs. UniProt-GOA, weighted by bitscore and sequence identity), with the blend weight tuned on the validation set; noted that the simplified NN-only model already achieves "approximately 90-95% of the full model's performance" — a modest, not dramatic, lift from adding the alignment-based half. — [6th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/evans-6th-place-solution-for-the-cafa-5-protein-fu)
- **CAFA-6, 11th place (T0chka)**: final ensemble is an **XGBoost learning-to-rank model** combining six component scores (HMLP, MLP+residual blocks, PyBoost, BLAST-KNN, naive prior, non-experimental UniProt annotations), with candidate GO terms drawn from the **union** of all six components' predicted term sets. No isolated per-component ablation/lift numbers were given in the fetched material. — [GitHub: T0chka/cafa6_11th_place_solution](https://github.com/T0chka/cafa6_11th_place_solution)

### Inferences
- Reported ensembling lift is very team-dependent and seems to depend heavily on how correlated/redundant the component methods are: teams blending truly heterogeneous evidence types (sequence vs. structure vs. literature vs. alignment) that each capture different failure modes report bigger relative gains (ProtBoost's staged ablation) than teams whose "ensemble" is mostly repeated instances of the same architecture (4th place's 25-network seed/fold average) or where one component already dominates (5th place's 98.7%-from-one-component finding).
- A learning-to-rank or tree-based meta-model (XGBoost/Random Forest/GCN) over component scores, rather than simple averaging, was the norm among examined top-10 CAFA-5 finishers and was reused unchanged in the CAFA-6 11th-place solution — this specific "diverse base learners + tree/GCN meta-model" recipe looks like the most transferable, competition-agnostic pattern found in this research.

### Gaps
- Could not find an isolated ensembling-lift number for GOCurator (1st place) or the exact weight the 3rd-place team's ensemble assigned to its CNN-processed electronic-annotation branch.

## What tools/libraries did top solutions rely on?

### Takeaway
A consistent, mostly open-source toolchain recurs across both competitions: Hugging Face-style PLM checkpoints (ESM2/ESM-1b/ProtT5/ProtBERT/Ankh) for embeddings, BLAST/DIAMOND/Foldseek/TM-align for alignment- and structure-based signal, gradient boosting (Py-Boost specifically, plus XGBoost/LightGBM), and PyTorch for neural heads — with GO-graph handling code typically custom-built per team rather than a shared standard library.

### Cited Findings
- **CAFA-5, 1st place**: InterProScan (protein domain/family annotation), PubMedBERT (text embeddings for literature), Doc2Vec and TF-IDF (literature representation), AttentionXML (extreme multi-label classification library). — [1st place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/gocurator-1st-place-solution-for-the-cafa5)
- **CAFA-5, 2nd place (ProtBoost)**: Py-Boost (the team's own gradient-boosting library, open-sourced), scikit-learn-style LogReg, a custom Graph Convolutional Network implementation for stacking; full code released at [github.com/btbpanda/CAFA5-protein-function-prediction-2nd-place](https://github.com/btbpanda/CAFA5-protein-function-prediction-2nd-place). — [ProtBoost paper](https://arxiv.org/pdf/2412.04529)
- **CAFA-5, 5th place (StarFunc)**: BLASTp, Foldseek, TM-align (structural alignment), LightGBM, STRING database (PPI), Pfam (domain families). — [5th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/hfm7zc-5th-place-solution-for-the-cafa-5-protein-f)
- **CAFA-5, 6th place**: blastp and DIAMOND for sequence search against UniProt-GOA. — [6th place writeup](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction/writeups/evans-6th-place-solution-for-the-cafa-5-protein-fu)

- Py-Boost's reappearance, unprompted, in an independent CAFA-6 team's toolkit two years after its CAFA-5 debut suggests it has become a genuine community-adopted tool for this specific problem shape (huge multi-label target space), not a one-off trick — worth treating as a serious candidate technique for this project if this project's own pipeline ever needs a non-neural, GO-term-count-agnostic ensemble member.
