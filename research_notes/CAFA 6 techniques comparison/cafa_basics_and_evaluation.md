# CAFA Basics and Evaluation (CAFA1–CAFA6 background)

## What is CAFA's task definition?

### Takeaway
CAFA (Critical Assessment of Function Annotation) is a recurring, community-run blind-prediction challenge in which participants predict which Gene Ontology (GO) terms — across the three independent sub-ontologies Molecular Function (MF/MFO), Biological Process (BP/BPO), and Cellular Component (CC/CCO) — apply to a given protein, based primarily on its amino-acid sequence (and optionally other data). It is explicitly modeled on CASP (Critical Assessment of Structure Prediction)'s prospective, blind-evaluation design.

### Cited Findings
- CAFA is "a community effort held to understand the field of computational protein function prediction," run "every three years, since 2010," in which organizers "release a large number of proteins whose functions are unknown or partially known" for prediction. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- The prospective evaluation design directly parallels CASP's model for structural biology: "ground truth annotations used for evaluation did not exist during model training, thereby reducing data leakage and providing a realistic assessment of predictive performance." — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- GO terms are organized as a directed acyclic graph (DAG) "where nodes (concepts or functional terms) are connected by relational ties, with more specific terms serving as descendants of broader, more general terms," and are split into three independent aspects (MF, BP, CC) that are evaluated separately. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- On Kaggle, CAFA5's task was framed for a general ML audience as: "develop a model trained on the amino-acid sequences of proteins and on other data" to predict the GO terms associated with each protein, with GO's parent/child DAG structure noted explicitly. — [CAFA 5 Kaggle competition search summary](https://www.kaggle.com/competitions/cafa-5-protein-function-prediction)

### Inferences
- Because MF/BP/CC are evaluated as three separate sub-problems, a "protein function prediction" system is really three coupled multi-label classification problems sharing an input (the sequence), not one flat multi-label problem — this affects how metrics are aggregated (see evaluation section).

### Gaps
- No official CAFA source text was retrieved that defines "protein function prediction" in a single canonical sentence; the framing above is reconstructed from the CAFA5 report and Kaggle summaries rather than one quoted definition.

## What is the history of CAFA (CAFA1–CAFA5): organizers and evolution?

### Takeaway
CAFA has run roughly triennially since 2010–2011 (CAFA1) through CAFA5 (2023–2025), organized by an academic consortium centered on Iowa State University (Iddo Friedberg) and Northeastern University (Predrag Radivojac), with results historically published in *Nature Methods* / *Genome Biology* and presented at ISMB; each round has grown in scale, added new evaluation categories, and — starting with CAFA5 — moved from an independent open-call format to a Kaggle-hosted crowdsourced competition, which produced a roughly 20-fold jump in participation.

### Cited Findings
- **CAFA1 (2010–2011)**: the inaugural round; found that "machine learning methods significantly outperformed sequence-similarity-based searches" (e.g., plain BLAST); results published in *Nature Methods* (2013). — [Wikipedia: Critical Assessment of Function Annotation](https://en.wikipedia.org/wiki/Critical_Assessment_of_Function_Annotation); [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- **CAFA2 (2013–2014)**: expanded the scale/diversity of target proteins and ontologies/assessment scenarios, and introduced "improved metrics including customized semantic-precision recall based scores" (i.e., semantic-distance-style, information-content-weighted metrics); results published in *Genome Biology* (2016) — this is the paper "An expanded evaluation of protein function prediction methods shows an improvement in accuracy" (Jiang et al.). — [Wikipedia](https://en.wikipedia.org/wiki/Critical_Assessment_of_Function_Annotation); [arXiv:1601.00891](https://arxiv.org/pdf/1601.00891) (title/abstract only confirmed; full-text formula extraction failed due to size limits — see Gaps)
- **CAFA3 (2016–2017)**: incorporated large-scale experimental validation into the assessment pipeline, testing top computational predictions via experimental screens in *Candida albicans*, *Pseudomonas aeruginosa*, and *Drosophila melanogaster* ("synergy between experiments and computation"); published in *Genome Biology* (2019). — [Wikipedia](https://en.wikipedia.org/wiki/Critical_Assessment_of_Function_Annotation); [bioRxiv 653105](https://www.biorxiv.org/content/10.1101/653105v1.full)
- **CAFA4 (2019–2020 submission; evaluated through 2025)**: had the longest annotation-accumulation phase of any CAFA round (5 years) — 148 methods from 70 research groups (144 methods evaluated) were assessed on 46,205 unique benchmark proteins, drawn from 97,999 originally released target proteins. Predictions were submitted ~February 2020, with five successive evaluation timepoints from February 2021 through March 2025. Introduced a new "Partial Knowledge" (PK) evaluation category (see evaluation section) and expanded metrics to include both macro- and micro-averaged Fmax. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- **CAFA5 (2023–2025)**: the first round hosted in partnership with Kaggle Inc., which "facilitated participation from a large community of data scientists and computational biologists." Target set of 141,865 proteins across 90 species were released; training data comprised 142,246 proteins with experimentally validated GO annotations (from UniProt release 2022_05); submission deadline (t0) was 2023-08-21; final evaluation (te) occurred ~March 2025 (roughly 23 months later), yielding a final evaluation benchmark of 24,405 proteins with 234,529 accumulated annotations. The Kaggle format drew 1,625 teams from 78 countries and 2,850 submitted models — described as "a 22.2-fold increase in participating teams compared to CAFA4 and 17.6-fold increase in submitted models." — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- Lead/corresponding authors of the CAFA5 report: M. Clara De Paolis Kaluza (Northeastern), Iddo Friedberg (Iowa State), Predrag Radivojac (Northeastern, corresponding); other named organizers/co-directors across CAFA4/5 reports include Sandra Orchard and Maria J. Martin (EMBL-EBI/UniProt), Burkhard Rost, Christine Orengo, Marc Robinson-Rechavi, Dannie Durand, Steven E. Brenner, Casey S. Greene, Sean D. Mooney, and Silvio C. E. Tosatto. CAFA5 work was partially supported by NIH award R01GM145937. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/); [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- CAFA5's benchmark training set contained 31,466 distinct GO terms across the three aspects: BPO 21,285, CCO 2,957, MFO 7,224 (per a third-party aggregator summarizing CAFA5/CAFA6 GitHub solution repos; not independently verified against a primary CAFA5 source document in this research pass). — [WebSearch aggregation, unverified primary source](https://www.kaggle.com/competitions/cafa-6-protein-function-prediction)
- CAFA5's Kaggle leaderboard metric was a *single*, simplified number — the information-accretion (IA)-weighted Fmax averaged across the three GO aspects, computed only on the NK+LK evaluation settings during the live competition (PK was excluded from the live leaderboard and analyzed post hoc in the report). — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- CAFA proceedings/results have historically been presented at ISMB (Intelligent Systems for Molecular Biology). — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)

### Inferences
- The move to Kaggle for CAFA5 (and continued for CAFA6) represents the single biggest structural change in CAFA's history — not to the underlying scientific task, but to the participant pool (data-scientist generalists vs. bioinformatics specialists) and to how the standard multi-metric CAFA evaluation had to be compressed into a single Kaggle leaderboard number (IA-weighted Fmax only, excluding Smin/AUPR/PK from live feedback).
- The steady introduction of new evaluation categories each round (CAFA2: semantic/IC-weighted metrics; CAFA4: PK category, macro+micro Fmax; CAFA5: PK folded into the report scale, Kaggle format) suggests CAFA methodology itself evolves incrementally in response to the previous round's identified weaknesses — a pattern likely to continue into CAFA6.

### Gaps
- The CAFA2 paper's precise original formulas for Fmax/Smin/information content could not be extracted in this pass (WebFetch failed on the arXiv PDF due to a 10MB content-size limit); the CAFA4/CAFA5 report definitions (below) are used instead as the authoritative current-form definitions, which should be equivalent in spirit but may differ in some later refinements (e.g., conditional information content for PK is CAFA5-specific, not present in CAFA2).
- Exact CAFA1–CAFA3 participant counts, protein counts, and GO term counts were not confirmed in this pass — only CAFA4 (46,205 proteins, 148 methods/70 groups) and CAFA5 (141,865 target proteins, 142,246 training proteins, 1,625 Kaggle teams) numbers were confirmed from primary reports.

## What is the official CAFA evaluation metric, and how is it computed?

### Takeaway
CAFA's core metrics are protein-centric and threshold-maximized: **Fmax** (a maximized F-measure over a confidence threshold τ, computed in both micro- and macro-averaged forms) for precision/recall-based assessment, and **Smin** (minimized semantic distance over τ, combining "remaining uncertainty" and "misinformation") for a threshold-independent, error-cost-based assessment; both increasingly incorporate **information content / information accretion (IA)** weighting so that predicting rare, specific GO terms counts for more than predicting common, uninformative ones. On Kaggle (CAFA5, and apparently CAFA6), this whole toolkit is compressed into a single **IA-weighted Fmax**, averaged across GO aspects, as the live leaderboard metric.

### Cited Findings
- **Fmax** is defined as the maximum F1-score over all prediction-confidence thresholds τ: Fmax = maxτ F1(τ), where F1(τ) = 2·pr(τ)·rc(τ) / (pr(τ) + rc(τ)), evaluated per protein and then aggregated. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- Two aggregation variants exist: **macro-averaged Fmax** (precision/recall computed per protein first, i.e. pr(τ) = ΣTPᵢ(τ)/Σ|Pᵢ(τ)| and rc(τ) = ΣTPᵢ(τ)/Σ|Tᵢ|, summed/averaged across proteins) and **micro-averaged Fmax** (pool all predictions across all proteins first, then compute one global precision/recall/F1). CAFA4 explicitly reports both FmaxM (macro) and Fmaxμ (micro). — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- **Coverage (C)** — "the fraction of benchmark proteins for which each method made predictions" — is reported alongside Fmax, since a method needn't predict on every protein. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- **Smin** (minimum semantic distance): Smin = minτ √(ru(τ)² + mi(τ)²), where ru(τ) ("remaining uncertainty") is the sum of information accretion of GO terms present in the true annotation set but absent from the prediction at threshold τ, and mi(τ) ("misinformation") is the sum of information accretion of incorrectly predicted terms at that threshold. A perfect predictor has Smin = 0. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/); [ResearchGate figure summary](https://www.researchgate.net/figure/Overall-evaluation-using-the-minimum-semantic-distance-Smin-Evaluation-was-carried-out_fig7_289587686)
- **Information accretion / information content (IA)** for a GO term f is defined as "the negative binary logarithm of the conditional probability that term f is present given all parent terms are present" — i.e., IA(t) = −log₂ Pr(t | Parents(t)) (equivalently expressed as log(1/Pr(t|Pa(t)))) — estimated empirically from the frequency of term t (conditional on its parents already being annotated) across the UniProtKB reference annotation corpus. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/); [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- For CAFA5's new Partial-Knowledge (PK) setting specifically, information content is computed *conditionally* on the protein's pre-existing annotations: IA(T₁ | T₀) = Σ_{v ∈ T₁∖T₀} log(1 / Pr(v | Parents(v))) — i.e., only the information content of *newly added* terms (given the ones already known at t0) counts toward the score, rather than re-scoring already-known terms. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- The CAFA5 Kaggle leaderboard metric was simplified to a single number: "IA-weighted Fmax averaged across the three GO aspects," computed for the NK+LK settings only (live), with PK reserved for the post-hoc report analysis. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- A companion open-source tool, **CAFA-evaluator**, was built specifically to standardize/benchmark this metric family (Fmax based on the precision-recall curve; Smin based on the RU-MI curve; both computed across all thresholds) as "A Python Tool for Benchmarking Ontological Classification Methods." — [arXiv:2310.06881, CAFA-evaluator](https://arxiv.org/pdf/2310.06881)
- **AUPR** (area under the precision-recall curve) is referenced in the broader CAFA-adjacent literature as a threshold-independent complement to Fmax, but AUPR was explicitly *not* a primary metric computed in the CAFA4 report — "the paper does not explicitly define AUPR; precision-recall curves are mentioned but AUPR scores aren't computed as a primary metric." — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)

### Inferences
- Weighting by information content rather than counting all GO terms equally directly rewards models that correctly predict *rare, specific* functional terms (deep in the GO DAG) over models that only get generic, high-frequency terms (like GO root nodes or "protein binding") right — because a generic term's conditional probability given its parent is high (so its −log₂ Pr is low, i.e., low IA), while a rare, specific descendant term has low conditional probability (high IA). This directly implies that naive/majority-class baselines that just predict common terms will score poorly on Fmax/Smin despite potentially high raw accuracy — a design deliberately chosen to counteract GO's long-tailed term-frequency distribution (see structural-challenges section below).
- Because IA is estimated empirically from annotation frequency in the reference database (UniProtKB) and "frozen" at a fixed time point (t0) for NK/LK, and computed conditionally for PK, the weighting itself is dataset/version-dependent — it is not a fixed intrinsic property of a GO term, but recalculated each CAFA round against that round's UniProt release.
- The fact that AUPR is not a CAFA4 primary metric, while Fmax/Smin are, suggests CAFA's own methodological emphasis is on *threshold-optimized, per-protein* multi-label metrics rather than global ranking metrics like AUPR/AUROC — a genuinely different emphasis from generic multi-label ML benchmarking conventions, worth flagging for a technique-comparison report since it changes which properties of a model's output (its best achievable threshold's precision/recall trade-off) actually get rewarded.

### Gaps
- The exact micro vs. macro Fmax formula variant used specifically on the CAFA6 Kaggle leaderboard (and whether IA weighting is applied at the per-protein or global level) was not confirmed from a CAFA6 primary source; it is inferred here to match CAFA5's precedent based on a CAFA6 solution repo's use of `f_micro_w`.
- The original CAFA2 paper's exact formulas (as first published) were not independently retrieved due to a PDF fetch failure; the definitions above come from the CAFA4/CAFA5 reports, which may include later refinements not present in CAFA2's original formulation.

## What is the Open World Assumption / incomplete-annotation problem, and how does CAFA describe/handle it?

### Takeaway
CAFA organizers explicitly acknowledge that GO annotations are inherently incomplete and biased (absence of an annotation does not mean absence of function), and they address this not by trying to "fix" the labels but by using a **prospective, time-delayed evaluation design**: predictions are locked at a submission deadline (t0), and ground truth is only established later (te) from newly accumulated experimental annotations, so a method is scored only on annotations that did not exist (or were not yet curated) at prediction time.

### Cited Findings
- Direct organizer statement of the problem: "Experimental annotations contain errors and accumulate in a biased manner. The annotations also remain sparse and incomplete, with most proteins lacking comprehensive functional characterization. This makes it difficult to distinguish between truly absent functions and those simply not yet experimentally validated." — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- The organizers frame this as requiring "robust assessment frameworks that can evaluate predictions against newly accumulated experimental annotations rather than relying on static benchmarks," i.e., a structural (evaluation-design) response to the open-world problem rather than a labeling fix. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- Concretely, this is implemented via three temporal checkpoints: tℓ (target/protein-release date), t0 (prediction submission deadline — the ontology itself is also frozen at this/the release point, denoted Gtℓ), and te (evaluation date, when accumulated new experimental annotations are checked against submitted predictions). For CAFA5: tℓ = 2023-01-01, t0 = 2023-08-21, te ≈ March 2025 (~23 months later). — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- Only experimentally-validated GO evidence codes are used to establish ground truth (both at t0, to define NK/LK/PK status, and at te, to define the positive labels): EXP, IDA, IPI, IMP, IGI, IEP, HTP, HDA, HMP, HGI, HEP, TAS, IC — explicitly excluding electronic/inferred annotations (e.g. IEA) that could otherwise leak information or reflect curator/algorithmic bias rather than direct experimental evidence. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- CAFA4's report separately flags a related leakage risk: "Inclusion of text mining methods can be a source of data leakage. Such methods can include training on experimental annotations from publications published before the submission deadline, that were not in the corresponding UniProt databases" — noting that the fraction of such not-yet-curated-but-published annotations "is estimated to be over 98%" at any given time, which is itself framed as evidence of just how incomplete formal database annotation is relative to the literature. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- CAFA4 also notes that as CAFA methods are evaluated across multiple subsequent rounds, "the advantage of text-mining methods disappears" — implying the prospective, multi-round design self-corrects for this particular leakage vector over time. — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- The organizers describe the field's fundamental incompleteness bluntly: "The problem of function prediction remains unsolved." — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)

### Inferences
- The open-world problem is why CAFA cannot simply treat "no annotation" as a hard negative label the way a typical supervised ML benchmark would; this is precisely why the NK/LK/PK evaluation categories exist (see next section) — each is a different way of carving out exactly the subset of (protein, term) pairs where the "no annotation yet" state is known to later resolve to "annotated," so scoring is only ever done where a genuine, dated ground-truth transition is observed, never on an assumed-negative.
- This design has a direct implication for anyone building a CAFA-style local training pipeline (as in this repo's `generate_dataset.py`): because raw `train_terms.tsv` rows are known to be a *severe undercount* of true positive protein–GO-term pairs (this repo's own CLAUDE.md notes "~98% of a protein's implied ancestor annotations aren't spelled out as explicit rows in the raw file," which is a related but distinct manifestation of the same incompleteness problem — true-path-rule ancestor propagation, not future discovery), any local training-time treatment of "absent GO term" as a confident negative is a modeling assumption that departs from CAFA's own more careful stance on the open-world problem.

### Gaps
- No explicit CAFA documentation was found describing the open-world/incomplete-annotation problem using that exact machine-learning terminology ("open world assumption," "PU learning," "positive-unlabeled") — the organizers' own language is domain-specific (annotation "sparsity," "bias," "incompleteness") rather than borrowed from the ML positive-unlabeled-learning literature. Any explicit connection to PU-learning framing is an outside inference, not something CAFA states itself.

## What are the known structural challenges of the task?

### Takeaway
Beyond the open-world annotation problem, CAFA's task carries at least four distinct, well-documented structural difficulties: (1) severe class imbalance / long-tailed GO term frequency, (2) the GO DAG's "true path rule" requiring hierarchical annotation consistency, (3) train/test protein novelty (via the NK/LK/PK prospective design), and (4) a widening evaluation gap as annotation databases mature (fewer wholly-unannotated proteins, more "partial knowledge" proteins) — a trend CAFA's organizers explicitly link back to problem (1)/(3) and used to justify introducing the PK category.

### Cited Findings
- **True path rule / DAG propagation**: "All annotations were propagated according to the GO rules of the relations is_a, part_of, regulates, negatively_regulates, and positively_regulates. That is, if a protein is annotated with term t, it is implicitly annotated with all ancestors of t in the GO DAG." — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- CAFA5 also froze the ontology graph itself at the target-release time point (Gtℓ), so that "predictions must be made on the ontology structure frozen at the target release time point tℓ" — meaning GO's own structure (term definitions, hierarchy edges) is versioned and pinned per-round, not treated as a static universal reference. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- **Class imbalance handled via IC weighting, not resampling**: rather than uniformly weighting all GO terms (which would over-reward correctly guessing abundant, generic terms), CAFA's IA(t) = log(1/Pr(t|Parent(t))) formula "down-weights abundant terms and up-weights rare functional annotations, naturally addressing class imbalance without explicit rebalancing" at the metric level (as opposed to the training-data level). — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- CAFA4's report separately flags awareness of hub-like, highly-connected, low-information terms — explicitly excluding the MF term "protein binding" (GO:0005515) from at least part of its assessment, and noting that UniProt's own annotation bias ("more annotations from well-studied proteins and functions") is partly evidenced by "the relatively high accuracy of the Naive baseline method" (i.e., a baseline that just predicts term frequency priors performs deceptively well, a classic symptom of class imbalance / long-tailed label distribution). — [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- **Train/test protein novelty via NK/LK/PK**: precise organizer definitions (CAFA5 report) —
  - *No-Knowledge (NK)*: proteins with **zero** experimentally validated GO annotations, in **any** aspect, before t0; predictions scored only against new annotations discovered in the t0→te window.
  - *Limited-Knowledge (LK)*: for a protein with prior annotations in aspect(s) A but not aspect(s) B, predictions are evaluated **only** in the previously-unannotated aspect(s) B.
  - *Partial-Knowledge (PK)*, new starting CAFA4/formalized in CAFA5: proteins that **already had** experimentally validated annotations in a given aspect before t0, and gained **additional** annotations in that **same** aspect during t0→te; only the newly-added terms (Pᵢ(τ) ∖ T_{t0,i}) are scored, explicitly excluding terms already known at t0.
  — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/); consistent phrasing in [CAFA4 report, PMC13174626](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/)
- CAFA5's own evaluation-set breakdown shows PK now dominates: of the final CAFA5 evaluation benchmark, NK = 1,717 proteins/35,558 terms, LK = 2,294 proteins/35,622 terms, but **PK = 21,415 proteins/163,349 terms — 69.7% of the total** accumulated evaluation annotations. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- The organizers explicitly connect this shift to their trend of interest: "as annotation coverage increases across iterations, fewer proteins remain completely unannotated, making PK evaluation increasingly important for assessing a method's ability to refine and expand existing functional knowledge" — i.e., the NK setting (predicting function for a totally blank-slate protein) is becoming rarer and less representative of the real-world task as UniProt's overall annotation coverage grows round over round. — [CAFA5 report, PMC13142333](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/)
- Performance is measurably weaker in this newer, harder PK setting than in the classic NK/LK settings across CAFA4: "the performance is weaker in the newly introduced 'partial knowledge' evaluation category... highlighting the need for a new class of methods" that better leverage existing partial annotations to predict what will be discovered next (rather than just predicting cold-start function from sequence alone). — [Search summary of CAFA4 report](https://pmc.ncbi.nlm.nih.gov/articles/PMC13174626/); corroborated: [CAFA5 report abstract](https://pmc.ncbi.nlm.nih.gov/articles/PMC13142333/) ("identify the need for methods that better leverage existing annotations to predict those that will be discovered later")

### Inferences
- The rise of PK as the dominant evaluation category (70% of CAFA5's evaluation mass) has a significant implication for technique comparison: a model architecture optimized purely for "sequence → GO terms" cold-start prediction (the classic framing, and the one this repo's own `training_run.py`/ESM-2 classifier follows) is now being scored mostly on a task it wasn't designed for — predicting *incremental* new annotations for a protein that already has *some* known annotations — which is a meaningfully different problem (closer to link prediction/completion on a partially-observed annotation graph than to pure zero-shot sequence classification). This is a structural point worth foregrounding in the larger comparison report, since it may explain performance gaps between "sequence-only" and "annotation-graph-aware" techniques.
- Given this repo's own label space is built via full ancestor-closure propagation of `train_terms.tsv` under `is_a`/`part_of` only (per this project's `CLAUDE.md`), it does not use the full 5-relation propagation (`is_a`, `part_of`, `regulates`, `negatively_regulates`, `positively_regulates`) that CAFA5's true-path-rule propagation described above uses — meaning this repo's label space is a conservative subset of the full CAFA-consistent ancestor closure, not a mismatch, but worth noting as a scope difference for the comparison report.

### Gaps
- No precise, quantified figure for "class imbalance" (e.g., an average positive-rate percentage across the full CAFA5 or CAFA6 label space, analogous to this repo's own measured 3.58% figure for its 383-term coarse space) was found in the CAFA4/CAFA5 organizer reports themselves — the imbalance is described qualitatively (via the IC-weighting rationale and the "Naive baseline" symptom) rather than with a headline statistic.
- Whether CAFA6 keeps the same NK/LK/PK proportions as CAFA5 (69.7% PK) — or whether PK's share grows further, per the organizers' own stated trend — is not yet confirmable, since no CAFA6 organizer report exists yet (see prior section's Gaps).
